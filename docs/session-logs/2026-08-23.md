## What happened

The catalog stopped being three line costs and became a data model: applicability, declared
register writes, and write timing classes. `layout.ts` stopped naming template ids by hand
and started asking a selector. The golden comparator learned that a strobe's position is its
meaning.

## Two departures from the plan's own code sketch

Both forced by measurement rather than preference, which is the only reason to depart from an
approved plan.

### `applies.kinds` exists because `objects` and `perLineData` cannot separate the HUD from the field

The plan specified `Applicability = { objects, perLineData }`. Filling in the declared writes
meant reading the golden trace, and the trace shows the score band has the **same priming
shape** as the field loop — `.hudDigit` is `sta WSYNC` then the GRP writes, exactly like
`.openField`. Both bind two objects. Both rewrite per-line data.

So the plan's own lowest-cost tie-break would have handed the **field** to the cheaper score
kernel. `applies.kinds` carries the distinction instead, and it was proved load-bearing
rather than assumed: letting `bcd-score-band` draw a loop makes it win the field, the entry
line vanishes, 158 becomes 159, and the ledger gate fires — nine tests red.

### `perLineData` moved onto the entry, and `entryLines` stayed measured

Reading the same trace produced the qualification that stops `entryLines` being computed:

The reference kernel's comment says the HUD is `2 + 8 + 2 = HUD_LINES`. **The trace says 3
blank, 8 glyph, 1 blank.** The priming line at 42 is counted as a glyph line and the trailing
blank is counted twice — two errors that cancel, so the band total is right and the frame
total is right. The identical defect class step 2 found in this kernel, and the reason the
ledger gates on the sum rather than on the author's arithmetic.

The consequence: `bcd-score-band` has the priming shape and costs **0**, because its entry
line falls *inside* the band's authored height rather than on top of it. Deriving `entryLines`
from `perLineData` would have given the score band an entry line it does not have, a 193-line
frame, and a build that fails on a scene that works.

## The comparator gap was real, not hypothetical

`tests/fixtures/timing/resp-shift.asm` is `resp-base.asm` with ten more cycles of delay
before the strobe. Both write `$00` to `RESP0` on line 40; the player lands thirty colour
clocks apart. **`compareGolden` returned zero mismatches** — review 0.2 §1.1's complaint,
reproduced as two ROMs.

The `exact`/`blank`/`deadline` split catches it now, and the tank-arena golden still passes
untouched, which is the check that mattered: the golden was recorded from this emulator, so
the clock in the file is the clock the ROM produces. It was **not** re-recorded.

The fixtures cost one correction of their own: both first produced 261-line frames, 3/37/191/
30. The RESP0 strobe runs on visible line 40, which the loop's first WSYNC then ends, so
`ldx #191` was one short.

## Four gaps found by re-reading the increment's own diff

None was caught by the tests written for the tasks.

1. **`positionMismatch` ran before the equality check.** A record that had drifted to a
   different *line* would be reported as a pixel discrepancy and the line shift never named —
   which bites precisely in 5b, where generated positioning is the likeliest thing to land
   wrong.
2. **`exitLines` influenced selection but never reached the ledger.** All three entries
   measure 0, so nothing was wrong yet; a non-zero one would change *which* template wins and
   quietly produce a short frame. `E505` refuses it now.
3. **The comparator's `blank` branch had never once fired.** Covered by hand-built records.
4. **A determinism test asked the same question twice**, which proves nothing — the same input
   gives the same answer either way. It now feeds the catalog reversed.

## Limitations recorded rather than left implicit

- The comparator compares the **pixel**, so two strobes at different clocks *inside*
  horizontal blank both store −1 and compare equal. Added to the unmeasured list; recording
  the colour clock is the fix and it changes the golden file format.
- No template declares a beam-sensitive write yet — positioning is the runtime's own routine,
  charged per band boundary — so the agreement test compares `deadline` with `deadline`
  seventeen times. It carries an assertion saying so, which turns red the day that stops being
  true.
