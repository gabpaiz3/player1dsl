# Session log — 2026-08-29

**Branch:** `step3-plan3-layout-and-catalog`
**Scope:** plan 3, increment 5b — the frame driver, the emitter, `p1 build --static`, and the
first ROM this compiler has ever produced.

## What happened

`p1 build --static examples/tank-arena` emits a real 4096-byte cartridge image. It runs 262
scanlines split 3/37/192/30, and **the visible region of golden frame 0 is reproduced record
for record** — every TIA write from line 40 to the end of the frame, in order, from a ROM the
compiler emitted against a ROM a human wrote.

That is the first thing in plan 3 that can falsify the ledger. Everything before it was the
compiler asserting what the compiler computes: `expect(ledger.total).toBe(192)` is true by
construction. 158 is now 158 scanlines in an image.

## Decisions made

| Decision | Rationale |
|---|---|
| Counted WSYNCs, not `TIM64T` | `wsync-only.asm` is the ROM Stella validated at 262 lines; the timer's T is still PENDING a Stella reading, and the reference kernel's own two timer constants were **both** off by one until a measurement corrected them. Building the first compiler-emitted ROM on the unvalidated mechanism would put an unmeasured number under everything the increment claims to check. |
| `setupLines` is a parameter, not a guess | Vertical blank is 37 lines *total* and positioning spends four of them inside setup. An emitter writing `ldx #37` afterwards produces a 266-line frame — which is what all three kernel fixtures did. The caller built setup from routines whose costs the catalog declares, so it knows. |
| A row group's code comes back in three parts | `hoist` is writes that do not belong on this group's own lines. See below — it is a measured hblank budget, not a copy of the reference. |
| The last vertical-blank WSYNC sits **outside** its loop | The first visible line writes `PF0`, read at pixel 0, and the reference already fills that line's blank to colour clock 66 of 68. The two cycles a `dex`/`bne` fall-through spends come straight out of it. |
| The digit font is pinned to the golden, not to the file it came from | Comparing it to `tank-arena.asm` would only prove the copy is a copy. The golden records the bytes the reference ROM actually put in GRP0 and GRP1. |
| The tank sprite is not copied at all | `SpriteIr.rows` already carries what the `.p1` declares. Task 15 step 3 said to take both from the reference; that is right for the font, which the `.p1` has no way to express, and wrong for the sprite, which it does. |
| NTSC region constants moved into the runtime | Two copies of 192 — one the ledger gates on, one the ROM counts down — is two places to disagree, and the disagreement would be a ledger that balances over a ROM that is a line short. The ledger exists to catch that, so it must not cause it. |

## Why the field's colour writes are hoisted onto the wall's setup line

The reference writes `COLUP0`/`COLUP1` on line 57, inside the top wall's run, rather than on
the field's own entry line at 65. Reproducing that placement needed a reason that was not
"the reference did it", and there is one: **the entry line has no horizontal blank left.**

Line 65 already spends its blank on PF0 (deadline pixel 0), PF1 (16), PF2 (48) and two GRP
clears. The golden shows GRP0 landing at **pixel 1** — already past the end of blank. Two
colour writes added there land around pixel 31. They would be safe *only* because that line
clears GRP to `$00` by construction, so nothing reads COLUPx on it — a write whose timing
nothing in the model constrains, one scene edit away from mattering. That is this plan's own
"an omitted cost becomes an assumed zero", turned on the emitter.

The previous row group's setup line has blank to spare, so they go there. The composer emits,
for each group *i*: `setup[i]`, `hoist[i+1]`, `body[i]`.

## Every difference filtered out of the frame-0 comparison, and why

Two, both named in `packages/emulator/test/static-build.test.ts` where the filter is applied.
Nothing else is excluded.

### 1. `CXCLR`

Collision handling, which is plan 4. Filtered from **both** sides so neither can hide behind
it.

### 2. Everything before the first visible line

The reference reads two joysticks and rebuilds two font pointers in vertical blank. A static
build has no rules and no changing scores, so it reaches the positioning routine **one
scanline earlier**: `HMP0` at line 4 rather than 5.

Vertical-blank line *placement* carries no ledger claim — positioning there is free precisely
because nothing is drawn — and padding to realign would be tuning a constant to make a number
come out. What those writes **do** is still compared, by a separate test, on
`(register, value, pixel)` ignoring the line:

| | golden | ours |
|---|---|---|
| `HMP0` | `$60` px40 | `$60` px40 |
| `RESP0` | `$60` px52 | `$60` px52 |
| `HMOVE` | `$60` blank | `$60` blank |
| `HMP1` | `$40` px70 | `$40` px70 |
| `RESP1` | `$40` px82 | `$40` px82 |
| `HMOVE` | `$40` blank | `$40` blank |

Identical. That is Task 13's `exact` class doing real work for the first time.

**The plan's floor is inside the window and compared exactly:** the band-boundary
`RESP0`/`RESP1`/`HMOVE` that place the 5-line transition, the wall `PF0`/`PF1`/`PF2` that
place the two 8-line runs, and the HUD `GRP0`/`GRP1` that place the 12-line glyph band. No
comparison was weakened; the line partition fallback the plan authorised was not needed.

### Both known-positives fire

Moving one tank one scanline is caught as a `record` mismatch. Sliding a score digit eight
pixels along its line is caught by the **clock** comparison — the gap `resp-shift.asm` was
written for, now guarding generated output.

## Findings that contradicted a prediction

### `p1 build`'s default output path destroyed the DASM parity baseline

`build/<name>.bin` is where the plan says the compiler writes. It is also where
`examples/tank-arena/reference/build.sh` put DASM's output. The CLI test exercising the
default path silently replaced `build/tank-arena.bin`, after which the parity test reported
**our assembler disagreeing with DASM about bytes DASM never produced**.

It cost half an hour to see, because the failure names a byte offset in a file neither side is
actually arguing about. A user running `p1 build` would lose their afternoon. DASM's output
now goes to `build/reference/`, and CI confirms the split end to end: 6 parity tests, 0
skipped, byte-identical on all six ROMs.

The lesson is not "be careful with paths". It is that a *default* which collides with an
existing artifact is a defect even when every test passes, because the collision is silent.

### The new `-o` parsing dropped the path argument whenever `-o` was absent

`outputAt + 1` is index 0 for a flag that is not there, so the first positional was filtered
out. Caught immediately by the existing `p1 check` tests — which is the argument for a suite
that runs whole rather than per-file.

### A test that could not fail, written while guarding against that exact defect

The `check`/`build` ledger-agreement test sliced on a header string that padding made wrong.
Both sides came back empty, and two empty strings are equal. It now asserts the slice found
something *before* comparing. `docs/testing.md` §3, produced in the act of defending against
someone else's version of it.

## What Stella showed

`sh scripts/stella.sh` opened the compiler-built ROM. Stella's frame-stats overlay reports:

```
262 / 60.0Hz => NTSC*
60.0fps @ 100% speed
4K* (4K)
```

**262 scanlines, NTSC, 60Hz, a 4K image — confirmed by a second implementation.** Our
emulator says the same, and until now that was one implementation agreeing with itself.

The picture: a white arena border framing a black interior, the scores **3** and **5** in
white at the top, a **red** tank upper-left and a **blue** tank lower-right, and nothing
moving. That is the scene `tank-arena.p1` describes.

Why the look matters, and why no test here replaces it: **our emulator is a timing model and
does not render pixels at all.** It cannot see a wrong playfield bit order, wrong REF
mirroring, or a sprite one column off — and neither can the golden, which was recorded from
this same emulator, so an error shared by the model and the golden is inherited by both ROMs
and compares equal. This is the precise class of defect a second implementation catches and
ours cannot.

`sh examples/tank-arena/reference/run.sh` opens DASM's build of the hand-written kernel for a
direct side-by-side.

### And a third instance of the same collision

`run.sh` still pointed at `build/tank-arena.bin`. After the artifact split that path holds the
**compiler's** ROM, so the script would have launched the compiler's output while announcing
the reference — and a side-by-side comparison of a ROM against itself passes perfectly. Found
while opening the two windows, not by a test. Both scripts now honour `P1_EMULATOR`, the name
SPEC §7 gives it.

## Still unmeasured, carried forward to plan 4

Unchanged from [2026-08-21](2026-08-21.md), plus:

- **Our TIA model's systematic errors**, per the paragraph above.
- **Strobes inside horizontal blank.** The golden format stores the pixel, so two RESPx
  strobes at different clocks inside blank compare equal. Recording the colour clock is the
  fix and it changes the file format.
- **The kernel's zero page is allocated separately from `allocateRam`.** The static build
  assigns its own scratch — an actor's live position, the graphics byte computed one line
  ahead — which no source line asked for. Plan 4 must unify the two, because a rule that
  moves an actor writes the same byte the kernel reads.
