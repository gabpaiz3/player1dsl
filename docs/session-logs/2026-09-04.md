# Session log — 2026-09-04

**Branch:** `step3-plan4-rules`
**Scope:** plan 4, increment 6 Tasks 5–13 — rule lowering, the cycle budget, the region-aware

## What happened

**`p1 build examples/tank-arena` emits a ROM whose entire 90-frame TIA-write trace matches the
hand-written reference kernel's. Zero mismatches.**

Not a static scene. A game that reads two joysticks, clamps four bounds, latches a collision
and debounces it — compiled from a `.p1` that names no scanline, no register and no cycle.
That is plan 4's stated goal and the close of step 3's walking skeleton.

357 tests, `npm run check` green.

## Decisions made

| Decision | Rationale |
|---|---|
| The compiler emits the **derived** bound, not the reference's | `movementBounds` gives 1/145/9/159; the reference clamps at 8/144/12/155, a hand-chosen margin. Reproducing it would be transcription. The golden's script never reaches a bound, so nothing diverges; clamping is asserted against the compiled ROM instead. |
| The clamp asymmetry lives in **lowering** | `movementBounds` says where the sprite may REST. `cpx #C / bcc` rests one below C, `cpx #C / bcs` rests on it — so lowering emits `xMin + 1` and `xMax`. Baking that into the bounds would give four numbers whose meaning depended on which side of the axis they sat on. |
| Movement in vertical blank, collision in **overscan** | Positioning reads the bytes movement writes, so movement comes first. Collision latches accumulate across the whole visible region, so reading them in blank would report the PREVIOUS frame's contact — a delay the reference does not have and the golden would see. |
| Each rule fragment ends on a **WSYNC** | See below. This is the session's largest finding. |
| No bound-reaching phase added to the input script | Plan Task 12 asked for one. The reference rests at 7 and the compiler at 1, so those frames could only ever be *excluded* from the comparison; ~70 of them would grow the golden with data nothing compares. Clamping is covered by the tests that can actually assert it. |
| `DEFAULT_STACK_RESERVED` is **8**, not 2 | Measured depth is two bytes. Eight buys four levels of nesting for a rule form that needs it. A margin with a reason, which the previous 16 was not. |

## Findings

### A frame whose length depended on the joystick

The first wiring put 290 cycles of movement code into vertical blank with **no WSYNCs**. The
beam advanced about four lines that `setupLines` never charged, and the frame came out **264
lines with zero vertical-blank lines**.

Worse than the arithmetic: the number of lines consumed depended on *which branch the input
took*. A frame length that varies with the joystick is exactly what the ledger exists to
prevent, and no amount of adjusting `setupLines` fixes it — the number is not constant.

Each movement direction and each collision rule now ends on `sta WSYNC`, so it costs a whole
line whichever way the branch went. Deterministic, and something the ledger can charge.

### `SWCHA` was emitted as `$0282`, which is SWCHB

The movement rule was reading the **console switches**. It compiled, assembled, ran, produced
a correct-length frame, and the tank simply never moved. Nothing failed.

`registers.test.ts` now holds the runtime's RIOT addresses to the emulator's. It would have
caught this in seconds instead of a debugging session.

### `cycleCost` was under-charging, and the first line of the first rule caught it

`lda SWCHA` reads `$0282` — absolute — but the cost model charged **every** unindexed symbol
as zero page: three cycles instead of four, four times per movement rule.

That is precisely the hazard `cycles.ts` had documented in its own comment:

> *"The moment a rule emits an unindexed absolute operand… this function under-charges it and
> the vertical-blank budget passes a frame that overruns."*

Task 9's budget gate would have inherited the lie. Unindexed symbols now default to
**absolute** unless the caller names them as zero page, with TIA registers known automatically
because the runtime already owns that table and RIOT registers deliberately not. A wrong guess
now costs more rather than less, which is the only direction a budget survives.

### Scores were never initialised in RAM

Invisible while the glyph was a baked assembly-time equate. The moment it became a pointer the
HUD would have rendered `0`. Every declared variable with a non-zero initial is now written at
reset.

### The last divergence was one record per frame

With everything else matching, `CXCLR` landed a scanline late: `lowerCollision` emitted its
WSYNC before the caller could strobe it. The strobe now comes after the last rule has read
what it needs and before the WSYNC that ends the line — the order the reference uses. That
single move took 90 mismatches to 0.

### The stack probe that measured zero

A first probe reported **0 bytes** of stack use across 80,000 instructions. It assumed the
stack pointer's reset value of `$FD`, while the emitted ROM sets `$FF` itself. Measuring
resting-minus-lowest rather than against an assumed origin made the real number appear: two
bytes, exactly as predicted.

## The risk that did not materialise

Task 8 switched the HUD to `lda (ptr),y`, one cycle dearer than `lda table,y`, twice per line,
in a band whose `GRP0` is read at pixel 0. **Measured rather than assumed:** both glyph writes
land at colour clocks 21 and 45, inside the 68-clock blank with room to spare. The digits the
pointers resolve to are pinned too — a rebuild that indexed the wrong glyph would still have
passed the deadline test.

## What Stella showed: nothing, and that is recorded rather than glossed

The capture **refused**. Windows would not grant Stella the foreground while another
application held focus, and the script now verifies the foreground window belongs to the
emulator before saving — because on two earlier attempts it photographed an unrelated browser
window instead.

So this increment has **no visual confirmation**. What stands in its place is stronger than
usual for once: a zero-mismatch trace comparison against a ROM a human wrote, which is a
second implementation of the *behaviour* if not of the picture. What it still cannot see is
colour, playfield bit order and REF mirroring — and nothing here changed those except the
glyph pointer, whose resolved digits are asserted.

`sh scripts/stella.sh` now builds the real ROM rather than `--static`, so a human can look in
one command.
