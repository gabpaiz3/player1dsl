## Findings that change the spec

Recorded in full in `examples/tank-arena/reference/NOTES.md`.

1. **§3.2 — the RIOT timer** is what makes VBLANK work bounded. Derived timer
   constants were off by a scanline: writing `TIM64T` loses up to 63 cycles to the
   internal prescaler.
2. **§3.3 — positioning costs** 2 scanlines per object, and `HMOVE` blanks 8 pixels
   on whatever line it is strobed.
3. **§3.4 — a band transition costs 5 visible scanlines** (2 per repositioned object
   plus 1 to absorb the HMOVE comb). SPEC.md §4.4's example bands sum to exactly 192
   and budget zero, so that layout does not fit on the machine. The cost is not even
   constant — it depends on how many objects cross and whether a line exists whose
   background can hide the comb.
4. **§3.6 — collision latches** report object *pairs*, not actors, and are *level*,
   not edge. `strategy multiplex` therefore silently converts every
   identity-dependent rule to software collision, and `score += 10` hides a debounce
   the hardware does not provide.
5. **Write ordering is a compiler obligation.** Three separate defects shared one
   root cause: *a loop exit leaves no horizontal blank*, so following writes land in
   the visible region. Where a `WSYNC` is unaffordable, writes must be ordered by the
   pixel at which each register is first read.

## The pattern worth remembering

Four times, arithmetic that was locally sound turned out wrong, and only looking at
the screen caught it:

| Predicted | Actual |
|---|---|
| `#43` → 262 scanlines | 261 — prescaler loss |
| Transition writes land in blank | pixel 136 — loop exits leave no blank |
| `175` + `WSYNC` holds 262 | 261 — the `WSYNC` costs zero, not one |
| Reordering fixes the wall notch | it was the HMOVE comb, a different cause |

This is the argument for spec review §1.1 stated in evidence: a planner claiming
"51 cycles free" from arithmetic alone would have been wrong four times in a single
200-line kernel. Step 2's emulator is not infrastructure — it is what makes the
product's central claim checkable.

## Part 2 — step 2: assembler and emulator

Built the TypeScript toolchain the roadmap calls for, and it immediately started
finding defects in the artifact it was built to validate.

### Emulator

6507 CPU (full documented opcode set, page-cross and branch penalties), 6507 address
decoding, TIA timing with WSYNC semantics, and the RIOT interval timer. Unknown opcodes
throw rather than acting as NOPs — a partial core that silently ignores an opcode
produces plausible-but-wrong timing, the exact failure it exists to catch.

**It found a bug in itself first:** the RIOT timer was frozen during WSYNC halts. The
timer runs off the system clock, not CPU execution, so every halt made it run slow and
stretched timer-bounded regions.

### Diagnostic ROMs

Debugging 264-vs-262 against the full kernel could not separate a WSYNC error from a
timer error, because the kernel exercises both. Two fixtures isolated them:

| ROM | Isolates | Emulator | Stella |
|---|---|---|---|
| `wsync-only` | WSYNC only, no timer | 262 | **262** ✓ |
| `timer-only` | timer only, no WSYNC | 263 → T=38 | **262 → T=37** |

**A prediction was made before measuring, and it was wrong** — I predicted Stella would
report 261 (T=36). The fixture existed precisely so a wrong prediction would be caught
rather than reasoned around.

Root cause: a 6532 timer write's first decrement lands on the NEXT cycle, not after a
full prescaler interval, so zero is reached at `1 + (N-1)*64` cycles, not `N*64`. For
`TIM64T #44` that is 2753 against 2816 — most of a scanline.

### The emulator found a defect in the reference kernel

`tank-arena` measured **3 / 37 / 193 / 29** while its comments claimed **3 / 37 / 192 / 30**.
The visible region borrowed a scanline from overscan, and **the two errors cancelled in
the total** — which is why neither Stella, nor the screen, nor five increments of visual
verification ever revealed them.

Corrected (`FIELD_LINES` 159 to 158, overscan timer `#35` to `#36`) and verified with
the emulator alone — the first kernel change in this project needing no Stella
round-trip.

### TIA write tracing

Every TIA write now records the scanline, colour clock and visible pixel it landed on.
`findLateWrites` reports writes that provably missed their deadline. That is the defect
class behind all three band-transition bugs from part 1, each of which cost a round of
screenshots and human inspection; one test run now covers all three.

Proved against a known-positive fixture first (`late-write.asm` commits the bug on
purpose), because "zero late writes on a clean kernel" also passes with a detector that
never fires.

Playfield deadlines are exact. GRP0/GRP1 sit behind an opt-in flag with a conservative
pixel-0 bound, because their true deadline is wherever the object sits — which needs
RESPx/HMOVE position tracking not yet built.

### Assembler

Byte-identical to DASM on all four ROMs, including the full 600-line kernel. Multi-pass
to a fixed point rather than two-pass: an operand can shrink from absolute to zero page
once its symbol is known, shifting every later address.

Learned rather than assumed: **DASM pads unwritten bytes with `$FF`, not `$00`.** On a
4 KiB cartridge that is most of the file.

### Review gating and CI

Neither compiling nor linting was gated anywhere — no linter existed, and
`.github/workflows/` was declared in SPEC.md §10 but never created. Added Biome, wired
biome and tsc into pre-commit (measured 249ms and 198ms), and put the 2.4s suite in CI.

Both gates were verified to actually *block*, not merely to pass on clean input.

The test suite no longer depends on DASM: emulator tests assemble their own ROMs, and
the parity test skips loudly when DASM output is absent.

**Failure 4 is the one that matters.** `pnpm install --frozen-lockfile` had been exiting

invisible locally and surfaced only when CI ran the command properly.

Three failed fixes for one problem is the signal to question the approach rather than
try a fourth. npm workspaces remove three of those five failure modes by construction.

## Decisions made in part 2

| Decision | Rationale |
|---|---|
| Emulator before assembler | The emulator is the measuring instrument and unblocks everything; the assembler unblocks nothing. |
| Diagnostic ROMs before datasheet | One mechanism per ROM produces evidence; reading the spec and tuning produces another plausible derivation, and this project is 0 for 6 on those. |
| Never tune a constant to make a number appear | An emulator fitted to one ROM agrees with Stella there and is wrong everywhere else, destroying the reason to build it. |
| Assert measured truth, not current behaviour | Tests stayed red for a commit rather than encoding a bug. |
| npm over pnpm | Four CI failures and three failed config attempts. |
| Lint and typecheck in pre-commit, tests in CI | ~450ms against 2.4s; a slow hook gets `--no-verify`'d into uselessness. |

## The pattern, extended

Part 1 recorded four cases where sound-looking arithmetic lost to a measurement. Part 2
added two more — the 6532's write semantics, and DASM's `$FF` gap fill — plus the
reference kernel's own region comments being wrong in two places that cancelled.

Six for six. This is the evidence base for spec review §1.1: a planner computing cycle
costs from arithmetic alone would have been confidently wrong every single time.
