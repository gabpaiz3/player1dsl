## Decisions made

| Decision | Rationale |
|---|---|
| Comments live on AST nodes, not in a side table | A formatter that deletes comments is unusable, and in this project the comments carry the reasoning. Attaching them to nodes means they survive any transformation that preserves nodes. |
| Blank lines are **not** preserved | The lexer drops them, so nothing downstream can know one was there. Preserving them means deciding whether a comment separated by a blank line is a *file* header or a comment on the declaration below — a real design question the tank-arena subset does not need answered. The example file was made canonical instead, and the limit is documented in `format.ts`. |
| `playfield border thickness 8, mode reflect` | Thickness in scanlines, because plan 3's ledger needs it as a number; reading it out of pixel art is indirection with no benefit. Attributes are order-free, and a repeated one is an error rather than last-wins — silently taking the last value means a typo changes the build without saying so. |
| `start` on the declaration that owns the value | The reference ROM begins with scores at 3 and 5. Frame 0 of the golden diverges without it. |
| Game IR carries no hardware detail | Asserted by a test that serialises the IR and searches it for `scanline`, `GRP`, `RESP`, `WSYNC`, `cycles`. "No hardware leaked in" is the kind of property that erodes one convenient field at a time. |
| Third-party game screenshots stay out of the repository | They are copyrighted commercial assets from AtariAge's archive, which AGENTS.md forbids. `docs/genre-survey.md` captures the analysis instead; `game-images/` is git-ignored. |

## Findings that contradicted a prediction

Four this session, all caught by tests rather than by reading.

### 1. `8x8` lexed as `number(8), name("x8")`

The digit run stopped at `8` and the identifier rule swallowed `x8`. `sprite tank 8x8:`
would have parsed as nonsense rather than failing. Only a digit-`x`-digit sequence now
produces the separator, so a bare `x` is still an ordinary name.

### 2. `cartridge 4k` lexed as `number(4), name("k")`

Same root cause, different surface. Rejoined in the parser rather than by teaching the
lexer about cartridge sizes, which would put a domain concept in the wrong layer.

### 3. `score p0` and `a.b` are one AST node with two surface forms

The formatter rendered `score p0 += 1` as `score.p0 += 1`, which no longer parses — caught
by the idempotency test, not by the byte-for-byte one. `MemberRef` now records whether it
was written with a dot, for the same reason `NumberLit` records its base.

### 4. The sprite cross-check passed vacuously

The test that compares `tank-arena.p1`'s sprite against `TankSprite` in the reference ROM
extracted the rows by splitting the assembly on the string `TankSprite` — which finds the
`lda TankSprite,y` *reference* first and returns an empty array. It compared `[]` against
`[]` and passed. A length assertion caught it. Anchored to the label definition at column
0, the transcription then matched byte for byte on the first try.

**This is the same defect class as the golden comparator's deadline check from plan 1** — a
test that cannot fail. Two in two plans; worth watching for as a pattern rather than
treating each as a one-off.

## Testing documentation and CI reporting

Wrote `docs/testing.md` and linked it from AGENTS.md in two places: the engineering
expectations bullet, and its own section.

**GitHub has no native test-results view** for vitest, JUnit XML, or any other format.
Three surfaces exist and the doc records the choice among them rather than only the
outcome:

- **Workflow annotations — adopted.** vitest's `github-actions` reporter emits
  `::error file=…,line=…,column=…`, which GitHub renders inline on the pull request diff.
  Built into vitest; no third-party action. **Verified by writing a deliberately failing
  test and reading the emitted annotation**, rather than trusting that the reporter exists
  and behaves as documented.
- **JUnit XML plus a reporting action — rejected.** Richer tables and history, but it puts
  a third-party action inside the CI trust boundary to improve presentation over
  annotations now obtained for free. Recorded with its reasoning so it can be revisited
  rather than rediscovered.
- **Job summaries — not worth it yet.** Native, but vitest emits no markdown summary, so
  adopting it means writing and maintaining a formatter.

Also bumped `actions/checkout` and `actions/setup-node` to v5, clearing the Node 20
deprecation warning both jobs had been emitting since before this session.

### The discipline the doc exists to record

Finding 4 above — a test that could not fail — is the second occurrence in two consecutive
plans. `docs/testing.md` states it as a rule rather than an anecdote:

> When a test asserts equality against data it extracted from somewhere, assert the
> extraction found something first.

The suite currently has two guards of this shape: the sprite cross-check asserts
`reference` has 8 rows before comparing, and the clamp test is paired with a *moves at all*
test, because "the position stopped changing" also passes when it never changed.

**Plan 3 has to be written before it can be executed.** Its shape, from the design:

- **Increment 4 — layout IR and the line ledger.** The crux of the whole step. Given
  `band hud height 12` and a `field` band with no height, the compiler must independently
  arrive at **158** field lines from `192 − 12 − 5 − 8 − 1 − 8`, using two measured rules:
  a band transition costs `2n + 1` lines for *n* repositioned objects, and a region change
  after a loop exit costs one more. **The ledger is a hard gate** — if it does not sum to
  exactly 192 the build fails, because a silently short frame is the defect class that
  survived five rounds of visual verification in step 1.
- **Increment 4b — three kernel-shape fixtures** (`scroll-field`, `ball-and-paddles`,
  `sprite-formation`), measured before the catalog interface is committed. The genre survey
  already predicts three gaps in the applicability vocabulary; 4b tests those predictions.
- **Increment 5 — the template catalog and selector**, with applicability conditions and
  costs declared as data.

**Two things to carry forward that are easy to lose:**

- **`within field` is parsed and resolved but not interpreted.** When plan 4 lowers it, it
  must reproduce the *measured asymmetry*: a lower bound rests at `X_MIN - 1` while an
  upper rests exactly at `Y_MAX`, because `bcc` skips only when already below while `bcs`
  skips at or above. A symmetric clamp puts the tank one pixel off and every later
  `RESPx`/`HMPx` write in the golden diverges.
- **`DEFAULT_STACK_RESERVED = 16` is a guess**, labelled as one in `packages/compiler/src/ram.ts`.
  The moment codegen exists, measure the deepest call chain and set it from evidence.

**Working conventions.** One session log per day at `docs/session-logs/YYYY-MM-DD.md`.
Branch per plan, push early (CI runs on every branch push, not only on PRs), open a PR when
ready, merge on green. npm workspaces, not pnpm. DASM and Stella are dev-only.

**The principle this project keeps re-earning:** derivation loses to measurement. Eleven
times now across four plans, arithmetic or reasoning that looked sound was wrong, and only
running the thing caught it. Do not tune a constant until a number appears — build a
fixture that isolates the mechanism and measure it.
