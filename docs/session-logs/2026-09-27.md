## What happened

**The missile lands two pixels right of its authored x, and so does the ball. The model was
right.** `MISSILE_STROBE_DELAY = 7` is measured now rather than assumed, and the ball shares it
by measurement rather than by analogy.

Worth recording as plainly as the times derivation lost. Across five plans this project has
mostly found reasoning wrong; here it was right, and the entry belongs in the same document as
the contradictions or the document is an argument rather than a record.

## Decisions made

| Decision | Rationale |
|---|---|
| Two fixtures, each a near-copy of `collide-playfield.asm` | The player's number is the only thing worth comparing against, so nothing else may differ: same block, same sweep, same `PosObjectX`, object index 2 or 4 instead of 0. Three comparable flips beat three unrelated numbers. |
| The ball keeps routing through `MISSILE_STROBE_DELAY` | It was measured equal, not assumed equal. A `BALL_STROBE_DELAY = 7` beside it would be a second answer to one question — the mistake `MOVE_RULE_LINES` was deleted for on 2026-09-08. |
| No separate known-positive ROM | Each fixture paints red *and* black across its own sweep, so neither verdict rests on a ROM that can only say one thing. `collide-two-objects.asm` needed a control precisely because its answer was black everywhere. |

## What the fixtures do NOT measure, checked rather than assumed

**The hblank positions.** Setting `MISSILE_HBLANK_POSITION` to 99 leaves every verdict above
unchanged, so these strobes land in the visible region and say nothing about the blank. The
UNMEASURED label stays and is now a checked statement instead of a hope — which is the
difference between it and the label `MISSILE_STROBE_DELAY` used to carry. A fixture that
reached them would have to strobe inside horizontal blank, which `PosObjectX` never does for
any authored x.
